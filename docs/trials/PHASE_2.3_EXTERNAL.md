## What failed

### Finding #11 — Semantic duplication undetected (CRITICAL)

`backend/app/main.py` already had:

```python
# line 53
@app.get("/health")
async def health():
    ...
```

TCAD-H worker appended at the end of the file:

```python
# line 146 (added by trial)
@app.get("/health")
def health():
    """Lightweight uptime probe..."""
    return {"status": "ok"}
```

Result: FastAPI registers two handlers for the same route. The second silently shadows the first. No error raised at import time.

Every gate in TCAD-H let this through:

| Gate | Verdict |
|---|---|
| `boundaries.yaml.global_deny` | PASS — main.py was allowed |
| WP `02_allowed_files.md` | PASS — explicit `backend/app/main.py` |
| `tcad_check_boundaries` firewall | PASS — path violations only |
| `py_compile` smoke test | PASS — syntactically valid Python |
| `ast.parse` smoke test | PASS — parses cleanly |
| `tcad_log close` validation | PASS — `11_worker_summary.md` complete |
| Merge preconditions | PASS — no uncommitted, no blockers |
| `git merge --ff-only` | PASS — fast-forward applied |

**The only thing that would have caught this is a reviewer agent or runtime endpoint test.** Neither exists in TCAD-H today.

This is the predicted failure mode mentor named "Comprehension Debt" / "Confident Fabricator":

> "Software se acumula a costo marginal cero, pero auditoría humana es constante biológica limitada."

The trial demonstrated it empirically.

## Other findings

### #7 (CRITICAL — fixed in-flight)

`TCAD_ROOT` env var only honored by `tcad_log.py`. Other 5 scripts hard-coded `SCRIPT_PATH.parent.parent`, creating WPs in framework dir instead of target.

**Fix applied:** all scripts now use `resolve_tcad_root()`. Committed: `fix(phase-2.3 finding #7)`.

### #8 (medium)

WP `02_allowed_files.md` assumed `backend/app/routers/health.py`. Edu-app inlines routes in `main.py`. Worker had to adjust scope mid-flight.

**Implication:** WP templates currently encode framework's own conventions. They need to be **structure-agnostic** or **autogenerated from target inspection**.

### #9 (medium)

Worktree did not inherit a Python venv. `pytest` failed with `ModuleNotFoundError: anthropic`.

**Workaround used:** invoke `$PROJECT/.venv/bin/python` explicitly.
**Fix needed:** worktree creation should detect target's venv and either symlink or document the activation path.

### #10 (medium)

Edu-app's `.venv` was created on a host that no longer exists (`/home/miguel/miniconda3` missing). Worker had no Python interpreter that could resolve project deps.

**Implication:** TCAD-H trial smoke gates degraded to syntax-only. Cannot run `pytest`.
**Doc needed:** "smoke prerequisites" section per repo.

## What this changes about Phase 2.5

**Mentor was right. Don't go to Atlas yet.**

Before Phase 2.5 (static graph), TCAD-H needs Phase 3 first:

### Phase 3 minimum — Reviewer Agent

The reviewer agent's job is exactly what humans cannot do at AI speed: **check for semantic conflicts before merge**.

Minimum implementation (no LLM):

1. **Duplicate route detection** — parse changed files, find decorated functions with same path. Flag.
2. **Duplicate function names** — if new `def foo(...)` collides with existing in same module, flag.
3. **Endpoint inventory diff** — compare FastAPI/Express/etc route table before vs after. Flag added/removed.

A simple `python3 scripts/tcad_review.py <wp-slug>` that performs these checks would have caught Finding #11.
